# สถาปัตยกรรมระบบ (ร่าง)

## ภาพรวม

```
┌──────────────────────────── Browser ────────────────────────────┐
│ React + TypeScript (Vite)                                        │
│  ├─ FactoryScene  — React Three Fiber (Three.js) ผังโรงงาน 3D     │
│  ├─ RoutePanel    — วิเคราะห์ระยะเดิน / Dashboard (Tailwind)       │
│  └─ lib/pathfinding — Dijkstra บนกราฟทางเดิน (คำนวณฝั่ง client)    │
└──────────────┬───────────────────────────────────────────────────┘
               │ supabase-js (REST + Realtime)
┌──────────────▼──────────────── Supabase ────────────────────────┐
│ Postgres: floors / zones / nav_nodes / nav_edges  (ผังโรงงาน)     │
│           parts / locations / stock / stock_movements (สต็อก)     │
│           inbound_receipts / inbound_receipt_lines (รับเข้า)       │
│           part_demand / pick_trips (วิเคราะห์ระยะเดิน)             │
│ Auth + Row Level Security · Realtime (อัปเดตสต็อกบนผัง 3D)        │
└──────────────────────────────────────────────────────────────────┘
```

### ภาพภายในอาคาร

- **เส้นพื้นตามมาตรฐาน 5S**: เหลือง = ขอบทางเดินรถยก/คนและพื้นที่ทำงาน, เส้นประขาว = แบ่งช่องทาง, ขาว = ตำแหน่ง rack/อุปกรณ์,
  ส้ม = พื้นที่รอตรวจ (MI3), แดง = ของเสีย (NG), เหลือง-ดำ = จุดอันตราย (บันได ลิฟต์ ฐานเสา), ทางม้าลายหน้าประตู
- ทางเดินวาดจากกราฟทางเดินจริง ทางเดินที่ถูก rack ขวางจะหายไปเองเมื่อย้าย rack
- **พาเลทบน rack มาจากยอดสต็อกจริง**: ยอด BOI ของแต่ละ lot ÷ จำนวนชิ้นต่อพาเลท (ปัดขึ้น) สีตาม Model ถ้าเกินความจุ rack จะวางล้นที่ทางเดินในโซนให้เห็น

### หน้าปรับผัง (โมดูลแยก)

เมนู **ปรับผัง** (ผู้ดูแลระบบ) แยกจากผัง 3D เพื่อให้เข้าใจง่าย — `web/src/components/layout-editor/`

- ผังมุมบนรายชั้น (SVG) มาตราส่วนจริง: กริด 1/6 ม., ทางเดิน, เสา, บันได/ลิฟต์ (ล็อก), แถว rack และสายพานไลน์ประกอบภายในโซน
- ลากโซนเพื่อย้าย, ลากจุดมุม/ขอบเพื่อปรับขนาด (ทีละ 0.5 ม.), ลากพื้นว่างเพื่อเลื่อน, ล้อเมาส์เพื่อซูม
- คีย์ลัด: ลูกศร (Shift = 2 ม.), R หมุน, Delete ลบ, Esc, Ctrl+Z / Ctrl+Y ย้อน/ทำซ้ำ (เก็บ 50 ขั้น)
- แผงขวา: แก้รหัส/ชื่อ/ชั้น/ตำแหน่ง/ขนาด, ความจุ rack, ข้อเตือน และ **ผลต่อระยะเดิน** (จุดรับเข้า → โซน, โซน → ไลน์นำร่อง) เทียบกับผังเริ่มต้น
- จุดสีเขียว = จุดหยิบของบนทางเดิน ระบบหาให้ใหม่ทุกครั้งที่ย้าย · ปุ่ม "ดูใน 3D" เปิดผัง 3D ที่โซนนั้น

หลักการคำนวณ (`web/src/lib/layoutEdit.ts`, `web/src/lib/floorPlan.ts`):

1. เก็บเป็น "ส่วนต่าง" จากผังหลัก (`changed / added / removed`) ผังหลักจาก Supabase จึงอัปเดตได้โดยไม่ทับงานที่แก้
2. ปิดเส้นทางเดินที่ตัดผ่าน rack, ไลน์ประกอบ, พื้นที่ MI3/NG/ชาร์จรถยก
3. หาจุดเข้า-ออกใหม่ = โหนดทางเดินที่ใกล้ขอบโซนที่สุด และยังเดินถึงได้ ⇒ ระยะเดินส่ง Part คำนวณใหม่ทันที
4. เตือนเมื่อโซนทับกัน, เกินขอบพื้น หรือไม่มีทางเดินเข้าถึง
5. Demo บันทึกในเบราว์เซอร์ (`localStorage`) — ระบบจริงควรบันทึกลงตาราง `zones` พร้อมผู้แก้และเวลา (ต้องมีระบบ login ก่อน)

ถ้าต้องการรายละเอียดสูงกว่านี้ (เช่น ปั้นใน Blender จากรูปถ่ายรอบอาคาร) สามารถ export เป็น glTF/GLB แล้วโหลดแทนโมเดลในไฟล์เหล่านี้ได้

## ระบบพิกัด

- พิกัด **site** หน่วยเมตร มองจากด้านบน แกน x ชี้ไปทางขวาของภาพดาวเทียม แกน z ชี้ลงล่าง (ไปทางถนน)
- แต่ละชั้น (`floors`) มีจุดเริ่มต้น `x, z` และมุม `rotation` ทำให้อาคารที่วางเอียง (อาคาร A ~12°) ยังวาง rack และทางเดินในพิกัดภายในแบบตั้งฉากได้
- ระยะเดินคำนวณจากพิกัด site เสมอ (`web/src/lib/geometry.ts`) จึงต่อทางเดินจากลานนอกเข้าไปในอาคารได้ถูกต้อง

## วิธีคำนวณระยะเดิน

1. **กราฟทางเดิน** (`nav_nodes`, `nav_edges`) แทนทางเดินจริงในอาคาร โดยแต่ละ zone มี `access_node_id` เป็นจุดเข้าถึง
2. ประเภทเส้นทาง:
   - `walk` = ระยะทางแนวราบ
   - `stairs` = ระยะแนวราบ + ความสูง × 2 (รวมชานพัก) และเดินช้ากว่าพื้นราบ
   - `lift` = ไม่นับเป็นระยะเดิน แต่บวกเวลารอลิฟต์และเวลาขึ้น-ลงเพิ่ม
3. ใช้ **Dijkstra** หาเส้นทางที่ "เร็วที่สุด" หรือ "เดินน้อยที่สุด" และเลือกไม่ใช้ลิฟต์ได้
4. **ระยะเดินต่อวัน** = ระยะเที่ยวเดียว × 2 (ไป-กลับ) × จำนวนเที่ยวต่อวัน

ค่าความเร็วที่ใช้คำนวณตั้งไว้ใน `TRAVEL_ASSUMPTIONS` (`web/src/lib/pathfinding.ts`) **ควรปรับตามเวลาที่จับได้จริงหน้างาน**

## ข้อเสนอแนะเพื่อลดระยะเดินไปไลน์ประกอบวงล้อ (ชั้น 2 และ 3)

1. **วัดก่อนแก้**: บันทึกจำนวนเที่ยวจริงของแต่ละ part (`pick_trips`) ประมาณ 1–2 สัปดาห์
2. **จัด part แบบ ABC ตามความถี่การเบิก**: part ที่เบิกบ่อย (กลุ่ม A) ควรอยู่บนชั้นเดียวกับไลน์ประกอบ
3. **Line-side Supermarket**: ทำจุดพักของใกล้ไลน์บนชั้น 2 และชั้น 3 แล้วให้ทีมจัดส่งเติมของเป็นรอบ ๆ (milk-run) โดยใช้ลิฟต์ แทนที่พนักงานประกอบต้องเดินไปเอาเอง
4. **เต็นท์ลานนอก**: ควรใช้เก็บของที่เบิกไม่บ่อยหรือของชิ้นใหญ่เท่านั้น เพราะเป็นจุดที่อยู่ไกลที่สุด
5. **Kanban**: ใช้การ์ดหรือ QR เป็นสัญญาณเติมของ เพื่อลดเที่ยวเดินที่เปล่าประโยชน์
