> ช่อง `[ ]` คือหัวข้อที่ยังต้องตอบ

## 1. เป้าหมายของระบบ

- [x] จัดการสินค้า/part และคลังรับเข้า (Inbound)

- [x] วัดระยะเดินและเวลาที่พนักงานใช้เบิก part ไปส่งไลน์ประกอบวงล้อ (ชั้น 2 และชั้น 3)
- [ ] KPI ที่อยากเห็นบน Dashboard (เช่น ระยะเดินรวมต่อวัน, สต็อกต่ำกว่า Min, ยอดรับเข้ารายวัน)

## 2. ผังสถานที่

### 2.1 ภาพรวมที่ยืนยันแล้ว

ที่มา: ภาพดาวเทียม (ดู [site/site-zones-draft.png](site/site-zones-draft.png)) โรงงาน UAM1 ติดถนนปู่เจ้าสมิงพราย

| พื้นที่ | การใช้งาน | สถานะ |
|---|---|---|
| A | อาคารหลัก 3 ชั้น มีไลน์ประกอบวงล้อที่ชั้น 2 และชั้น 3 | ✅ ยืนยันแล้ว |
| B, C | เต็นท์เก็บ FG รอขาย และใช้เก็บ Component ด้วย | ✅ ยืนยันแล้ว |
| E | สำนักงานใหญ่ (ติดถนน) | ✅ จากหมุดบนแผนที่ |
| D | เต็นท์ที่ใช้วาง Component เป็นบางครั้ง | ✅ ยืนยันแล้ว |
| F, G | ยังไม่ทราบการใช้งาน (แสดงเป็นพื้นที่โล่งเท่านั้น) | [ ] |
| เส้นทางจากเต็นท์เข้า A | เดินผ่านลาน → ทางเดินข้างอาคาร A → ประตูด้านหน้า (ฝั่งถนน) | ✅ ยืนยันแล้ว |

### 2.2 ค่าประมาณ (ต้องยืนยันหน้างาน)

| หัวข้อ | ค่าที่ใช้ตอนนี้ | สถานะ |
|---|---|---|
| สเกลภาพดาวเทียม | ~0.2 ม./พิกเซล (เทียบจากขนาดรถ) คลาดเคลื่อนได้ ±20% | [ ] |
| ขนาดอาคาร A | ~62 × 98 ม. วางเอียงประมาณ 12° | [ ] |
| ขนาดเต็นท์ | B ~31 × 25 ม., C ~29 × 30 ม., D ~17 × 38 ม. | [ ] |
| ความสูงแต่ละชั้น | 4.5 ม. | [ ] |
| ประตูหน้าอาคาร A | ด้านหน้าฝั่งซ้าย (ใกล้ทางเดินข้างอาคาร) | [ ] |
| บันได / ลิฟต์ขนของ | บันไดอยู่ด้านหน้าซ้าย, ลิฟต์อยู่กลางอาคารฝั่งขวา, ลิฟต์อนุญาตให้คนขึ้นหรือไม่? | [ ] |
| Rack และไลน์ประกอบภายในอาคาร A | ตำแหน่งสมมติ | [ ] |
| ประตูรั้ว (เช่น UAM1 Gate 2) | ยังไม่ได้ใส่ในผัง | [ ] |
| จุดรับเข้าสินค้า (ท่าขนของ) | ด้านหน้าอาคาร A (สมมติ) | [ ] |

> วิธียืนยันสเกลที่ง่ายที่สุด: วัดความยาวด้านหน้าอาคาร A ด้วยเครื่องวัดระยะเลเซอร์ หรือใช้ขนาดจากโฉนด/แบบก่อสร้าง แค่ 1 ค่าก็ปรับสเกลได้ทั้งผัง

## 3. สินค้า / Part

- [ ] จำนวน part (SKU) โดยประมาณ
- [ ] ข้อมูลที่ต้องเก็บ เช่น Part No., ชื่อ, หน่วย, Min/Max, รูปภาพ, Supplier
- [ ] ต้องติดตาม Lot / Serial / วันหมดอายุหรือไม่
- [ ] มีบาร์โค้ด / QR อยู่แล้วหรือไม่
- [ ] ปัจจุบันเก็บข้อมูลไว้ที่ไหน (Excel / ERP) และต้องย้ายข้อมูลเดิมเข้ามาหรือไม่

## 4. ขั้นตอนรับเข้า (Inbound)

- [ ] เริ่มรับเข้าจากเอกสารอะไร (PO / ใบส่งของ)
- [ ] ต้องมีการตรวจคุณภาพ (QC) ก่อนนำเข้าเก็บหรือไม่
- [ ] ใครเป็นคนเลือกตำแหน่งจัดเก็บ (Put-away): พนักงาน หรือให้ระบบแนะนำ
- [ ] ต้องพิมพ์ฉลาก / ติด QR ที่ตำแหน่งจัดเก็บหรือไม่

## 5. การเบิกส่งไลน์ประกอบ (หัวใจของการวัดระยะเดิน)

- [ ] รายชื่อ part ที่ไลน์ประกอบวงล้อใช้ แยกตามชั้น 2 และชั้น 3
- [ ] ความถี่ในการเบิก (จำนวนเที่ยวต่อกะหรือต่อวัน) และจำนวนชิ้นต่อเที่ยว
- [ ] ใครเป็นคนเดินเบิก และใช้รถเข็น / รถยก / เดินถือ
- [ ] จะเก็บข้อมูลการเดินจริงอย่างไร: สแกน QR ตอนหยิบและตอนส่ง, กรอกเอง, หรือ RFID/BLE
- [ ] จับเวลาเดินจริง 3–5 เส้นทาง เพื่อใช้ปรับค่าความเร็วในโมเดล

## 8. ขอบเขตแบ่งเฟส (ข้อเสนอ)

| เฟส | ขอบเขต |
|---|---|
| **0 — โครงร่าง** ✅ | ผังโรงงาน 3D ตัวอย่าง, คำนวณระยะเดิน, schema ฐานข้อมูล |
| **1 — ผังจริง** | ✅ ภาพรวม site จากภาพดาวเทียม → ใส่แบบแปลนภายในอาคาร A, ปรับค่าความเร็วตามที่จับเวลาได้จริง, รายงานระยะเดินต่อ part |
| **2 — คลังรับเข้า** | ทะเบียน part, ใบรับเข้า, จัดเก็บ (put-away), ดูสต็อกบนผัง 3D แบบ real-time |
| **3 — การเบิก & วิเคราะห์** | บันทึกเที่ยวเบิกด้วย QR, เทียบค่าจริงกับค่าที่คำนวณ, แนะนำตำแหน่งจัดเก็บใหม่ (slotting) |
| **4 — ขยายผล** | Login ตามบทบาท, แจ้งเตือนสต็อกต่ำ, export ไป Google Sheets/Excel |

## 9. สมมติฐานปัจจุบัน (ต้องยืนยัน)

- ขนาดอาคารและเต็นท์ประมาณจากภาพดาวเทียม ส่วนตำแหน่ง rack บันได ลิฟต์ และประตูภายในอาคาร A ยังเป็นค่าสมมติ
- ความเร็วเดิน 1.0 ม./วิ, เดินบันได 0.4 ม./วิ, รอลิฟต์เฉลี่ย 45 วินาที
- ระหว่างพัฒนา อนุญาตให้ดูผังโรงงานได้โดยไม่ต้องล็อกอิน ส่วนข้อมูลสต็อกต้องล็อกอินก่อน
